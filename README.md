## Проект 1. Предварительная проверка цены сделки с жилой недвижимостью - Самара

[Открыть ноутбук](Project_1_Real_Estate_Market_Analysis_Samara.ipynb)

**Вопрос из практики:** насколько цена по договору согласуется с рынком и в каких сделках отклонение настолько велико, что требуется дополнительная проверка (оценка банка, обоснование цены, налоговые последствия, риск оспаривания).

**Что сделано:**

- проверка качества данных по 500 сделкам вторичного рынка: пропуски, дубликаты, логические ошибки, выбросы;
- разведочный анализ: площадь, район (9 районов Самары), ремонт, год постройки, этаж;
- регрессия логарифма цены, коэффициенты которой читаются как процентные эффекты факторов;
- проверка на отложенной выборке и перекрёстная проверка;
- функция предварительной проверки: ожидаемая цена, допустимый коридор и заключение «в пределах коридора / требуется проверка».

**Что показал анализ (на смоделированных данных):**

- модель восстанавливает заложенные параметры: эластичность цены по площади близка к 1, евроремонт даёт около +16%, отсутствие ремонта около -12% относительно косметического;
- первый этаж снижает цену примерно на 5%, каждый год возраста дома - примерно на 0,3%;
- медианная цена за м² между самым дорогим и самым доступным районом различается в 1,7 раза;
- на отложенной выборке R² ≈ 0,99, средняя относительная ошибка около 4%; столь высокая точность объясняется тем, что смоделированные цены построены по формуле без скрытых факторов, на реальных данных она будет заметно ниже;
- коридор ±1,96σ содержит 99% сделок отложенной выборки.

Предварительная проверка не заменяет оценку рыночной стоимости: оценку проводит оценщик (ФЗ № 135-ФЗ «Об оценочной деятельности в Российской Федерации»).

## Проект 2. Анализ взыскания задолженности за ЖКУ и претензионно-исковой работы

[Открыть ноутбук](Project_2_Analysis_of_legal_claim_handling_activities.ipynb)

**Вопрос из практики:** как работает взыскание задолженности за жилищно-коммунальные услуги: сколько должников платит после претензии, как часто отменяются судебные приказы, какая доля долга возвращается, сколько времени занимает каждый путь взыскания и какая часть портфеля находится под риском истечения срока исковой давности. От ответов зависит очерёдность и стратегия подачи заявлений.

**Что сделано:**

- анализ реестра из 320 дел по трём видам платежей: коммунальные услуги, содержание жилого помещения, взносы на капитальный ремонт;
- воронка взыскания: претензия, судебный приказ, отмена приказа, иск, исполнительное производство, с 95%-ми доверительными интервалами;
- взыскиваемость по типам платежей и по возрасту долга;
- сроки взыскания по путям (через приказ, через иск);
- упрощённая оценка риска срока исковой давности (ст. 196 ГК РФ);
- очерёдность подачи по ожидаемой отдаче;
- те же показатели средствами SQL.

**Что показал анализ (на смоделированных данных):**

- после претензии оплачивают около 18% должников, судебные приказы отменяются примерно в 18% случаев, иски удовлетворяются в 81% случаев;
- по 41% дел, переданных на исполнение, что-либо взыскано; общая взыскиваемость по портфелю около 40% от суммы, не утратившей силу по давности;
- по долгам старше 36 месяцев взыскиваемость около 30% против 42% по остальному портфелю;
- медианный срок: после претензии - 22 дня, через судебный приказ - около 224 дней, через иск - около 294 дней;
- различия между типами платежей статистически неустойчивы: доверительные интервалы пересекаются, поэтому для выводов нужна реальная выборка.

Срок давности рассчитан упрощённо; расходы на взыскание и пени не учитываются.

## Подключение реальных данных

1. Выгрузить реестр дел или сделок.
2. Обезличить: удалить ФИО, адреса, номера лицевых счетов и иные сведения, позволяющие идентифицировать лиц, а также сведения, составляющие адвокатскую или коммерческую тайну.
3. Привести столбцы к схеме из раздела 2 ноутбука и сохранить: `data/deals.csv` (проект 1), `data/claims_register.csv` (проект 2).
4. Выполнить ноутбук целиком (`Kernel → Restart & Run All`): раздел проверки данных покажет ошибки учёта, остальные разделы и текстовые выводы пересчитаются автоматически.

Образцы смоделированных файлов создаются при первом запуске в папке `data/`.
